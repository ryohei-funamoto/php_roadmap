# Basic PHP Syntax

roadmap.sh/php の「Basic PHP Syntax」（`echo` / `print` / `print_r` / `var_dump`）の学習メモ。

| ファイル | 内容 |
|---|---|
| `01_syntax.php` | 基本ルール |
| `02_echo_print.php` | echo と print |
| `03_print_r_var_dump.php` | 変数の中身を確認する |
| `04_embed_in_html.php` | HTML に埋め込む |

実行方法：

```bash
php 01_syntax.php
```

## 1. 基本ルール（`01_syntax.php`）

- 文の終わりには `;` を付ける。ブロックは `{ }` で囲む。コメントは `//`、`#`、`/* */` の3種類。
- 変数は `$` で始まり、**大文字と小文字を区別する**（`$name` と `$Name` は別の変数）。
- 一方、`echo` などのキーワードや関数名は区別しない（`ECHO` や `STRTOUPPER()` でも動く）。ただし小文字で書くのが慣習。
- **ダブルクォートは中の変数を展開するが、シングルクォートは展開しない。** `\n` などのエスケープもシングルクォートでは文字のまま出る。

```
double: PHP
single: $name\n
```

## 2. echo と print（`02_echo_print.php`）

| | `echo` | `print` |
|---|---|---|
| 引数 | カンマ区切りで複数渡せる | 1つだけ |
| 戻り値 | なし | 常に `1` |
| 式の中で使えるか | 使えない | 使える（`$r = print "..."`） |

> **注意：** roadmap.sh には「print は関数」「複数の文字列を出力できる」とあるが、どちらも誤り。
> `print` も `echo` と同じ**言語構造**（PHP の文法の一部）で、引数は1つしか受け取れない。

実用上の違いはほとんどないので、普段は `echo` を使えば十分。

## 3. 変数の中身を確認する（`03_print_r_var_dump.php`）

- `echo` では配列を表示できない。中身を見るには `print_r` か `var_dump` を使う。
- `print_r` は読みやすさ重視。ただし `false` と `null` は何も表示されない。

```
Array
(
    [name] => Taro
    [age] => 20
    [admin] =>        ← false
    [email] =>        ← null
)
```

### falsy な値がすべて消えるわけではない

何も表示されないのは `false`、`null`、`""` の3つだけ。

| 値 | falsy か | `print_r` の表示 |
|---|---|---|
| `false` | ○ | （何も表示されない） |
| `null` | ○ | （何も表示されない） |
| `""` | ○ | （何も表示されない。もともと中身が空） |
| `0` | ○ | `0` |
| `0.0` | ○ | `0` |
| `"0"` | ○ | `0` |
| `[]` | ○ | `Array ( )` |
| `true` | × | `1` |

理由は、`print_r` が数値や真偽値などの単純な値を **`echo` と同じように文字列に変換して表示する**から。

- `false` → `""`、`null` → `""`（だから何も見えない）
- `true` → `"1"`
- `0` → `"0"`
- 配列は専用の形式で中身を一覧表示するので、空でも `Array ( )` と出る

### なぜ `false` は `"false"` にならないのか

PHP では、文字列に変換したときの結果が言語仕様として決まっている。
**値の名前（`"false"`）を文字にするのではない。**

| 値 | 文字列に変換した結果 |
|---|---|
| `false` | `""`（空文字列） |
| `null` | `""`（空文字列） |
| `true` | `"1"` |

`(string)false`、`strval(false)`、`"[" . false . "]"` のどれで変換しても空文字列になる。

`"false"` にしないのは、文字列を真偽値に戻したときに元の値と一致させるため。
PHP では `""` と `"0"` 以外の文字列はすべて `true` として扱われる。

```
(bool)""       → false
(bool)"1"      → true
(bool)"false"  → true   ← 空でない文字列は true になる
```

`false` を `"false"` に変換すると、戻したときに `true` になってしまう。
（JavaScript では `String(false)` が `"false"` になるので、他の言語の経験があると戸惑いやすい）

`false` や `null` を文字で表示したいときは、目的に合わせて別の関数を使う。

| 関数 | `false` の表示 | `null` の表示 | 主な用途 |
|---|---|---|---|
| `var_dump` | `bool(false)` | `NULL` | デバッグ（型も分かる） |
| `var_export` | `false` | `NULL` | PHP のコードとして書ける形で表示する |
| `json_encode` | `false` | `null` | JSON として出力する |

### `print_r` では見分けがつかない値

次の値は `print_r` では見分けがつかない。

- `false`、`null`、`""` → どれも何も表示されない
- `0`、`0.0`、`"0"` → どれも `0` と表示される

型の違いが重要な場面では `var_dump` を使う。

- `var_dump` は**型まで表示する**ので、デバッグではこちらが確実（`bool(false)`、`int(0)`、`string(1) "0"` のように区別される）。

```
array(4) {
  ["name"]=>
  string(4) "Taro"
  ["age"]=>
  int(20)
  ["admin"]=>
  bool(false)
  ["email"]=>
  NULL
}
```

- `print_r($x, true)` のように第2引数に `true` を渡すと、画面に出さずに文字列として返す。ログに書き出すときに便利。

## 4. HTML に埋め込む（`04_embed_in_html.php`）

- `<?php ... ?>` の中だけが PHP として実行され、外側の HTML はそのまま出力される。
- `<?= $x ?>` は `<?php echo $x; ?>` の短縮形。
- PHP だけのファイルでは、末尾の `?>` は書かないのが一般的（余計な空白が出力されるのを防ぐため）。
- 出力するときは `htmlspecialchars()` で `<` などの記号を無害な文字に変換する。セキュリティの分野で学ぶ XSS 対策の基本。

ブラウザで確認するには、PHP に付属の開発用サーバーを使う（止めるときは Ctrl+C）。

```bash
php -S localhost:8000
```

`http://localhost:8000/04_embed_in_html.php` を開く。

> **補足：** 生成日時が日本時間より9時間遅れるのは、PHP のタイムゾーンが未設定で UTC になっているため。
> 設定ファイルの分野（Configuration Files）で直す。

1. `echo` に3つの値をカンマ区切りで渡し、1行で出力する
2. `$price = 1980;` を、ダブルクォートとシングルクォートの両方で「価格: 1980円」と出力しようとして、違いを確認する
3. `["php", 8.5, true, null]` という配列を `print_r` と `var_dump` の両方で出力し、表示の違いを説明する
4. `$x = print "test";` の後に `var_dump($x);` を実行すると何が表示されるか、実行する前に予想する
